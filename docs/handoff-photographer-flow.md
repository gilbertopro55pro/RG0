# מסמך מסירה — מערכת ניהול תהליך צילום אירועים

## רעיון כללי
SaaS לצלמי אירועים: ניהול כל התהליך מסגירת האירוע ועד מסירת החומרים (תמונות, וידאו, אלבום). כל צלם נרשם עם משתמש/סיסמה, מנוי חודשי/שנתי.

## משתמשים
- **צלם** — בעל החשבון, אחראי בלעדי על כל אירוע שלו, גם אם צוות מבצע בפועל
- **צוות (עורכים/עוזרים)** — מבצעים שלבי עבודה, מסמנים שלבים כבוצע
- **לקוח סופי** — לא נכנס למערכת; מקבל עדכוני וואטסאפ ונכנס לגלריית wfolio

## חבילות (package types) וה-flow של כל אחת
1. **stills** — סטילס בלבד: סגירה → יום צילום → גיבוי → מיון → עריכה → העלאת גלריה → מסירה
2. **stills_reel** — סטילס + קליפ: כנ"ל + בחירת שיר → עריכת וידאו → אישור וידאו → מסירה
3. **stills_video** — סטילס + סרט ערוך: אותו flow כמו stills_reel
4. **full** — חבילה מלאה: סגירה → יום צילום → גיבוי → מיון → עריכה → העלאת גלריה → בחירת תמונות (לקוח) → בחירת שיר → עריכת וידאו → אישור וידאו → עיצוב אלבום → אישור אלבום → הפקת/הדפסת אלבום → מסירה
5. **full_second** — חבילה מלאה + צלם שני: כנ"ל + שלב "תיאום צלם שני" אחרי סגירת האירוע

**חשוב:** אישור וידאו ואישור עיצוב אלבום הם **שני checkpoints עצמאיים ומקבילים** (לא תלויים אחד בשני), למרות שמופיעים ברצף.

כל שלב מסומן כ"שלב פנימי" (מבוצע ע"י הצלם/צוות) או "מול הלקוח" (checkpoint שהלקוח מאשר/בוחר).

## תשלומים
לכל אירוע: מקדמה, יתרה לתשלום, תאריך יעד, סטטוס תשלום (שולם/לא) לכל אחד מהשניים בנפרד.

## פרטי אירוע נוספים שנאספים בפתיחת אירוע
שם לקוח, טלפון לקוח, תאריך אירוע, מיקום אירוע, שעת הגעה לצילומי משפחה.

## לוגיקת עדכונים ואוטומציה
- כל שלב שהצלם/הצוות מסמן כ"בוצע" → שולח (בפרודקשן: אמיתי; בדמו: מסומן ביומן) עדכון וואטסאפ ללקוח, **מהמספר האישי של הצלם** (נאסף בהרשמה) — כל צלם עם המספר שלו, מופרד לגמרי בין חשבונות
- ניתן **לבטל סימון "בוצע"** רק לשלב האחרון שסומן (כדי למנוע טעויות בלי לשבור את רצף התהליך)
- בשמירת אירוע חדש: נשלחת הודעת וואטסאפ אוטומטית עם פרטי האירוע המלאים; ונוצרת רשומה ביומן Google של הצלם
- **תבנית הודעת יומן Google:** סוג חבילה, תאריך אירוע, סכום מקדמה, סכום יתרה, שם לקוח, טלפון לקוח, שעת צילומי משפחה
- שדה המיקום לחיץ: לחיצה פותחת בחירה בין Waze ל-Google Maps לניווט

## הרשמה ותמחור
- מסך הרשמה דו-שלבי: (1) בחירת מסלול תשלום מתפריט נפתח — חודשי ₪50/חודש, שנתי ₪42/חודש (חיוב שנתי ₪500, חוסך 2 חודשים) (2) פרטי הרשמה: שם, טלפון, אימייל, סיסמה
- מודל תמחור: אחיד (flat) לכל הצלמים, לא לפי כמות אירועים/צוות

## אינטגרציות נדרשות (production בלבד — לא בדמו)
- **wfolio** — קבלת סטטוס בחירת תמונות מהלקוח
- **WhatsApp Business API** — שליחה אמיתית מהמספר האישי של כל צלם (sender-per-account)
- **Google Calendar API (OAuth)** — כל צלם מחבר את היומן האישי שלו בהרשמה

## עיצוב
פלטת פסטל מקצועית (לבנדר-כחול, מבטא פריווינקל רך), טיפוגרפיה: Frank Ruhl Libre (כותרות) + Rubik (גוף טקסט) + IBM Plex Mono (תוויות/נתונים), RTL מלא. תפריטי בחירה (חבילה, מסלול מנוי) כ-dropdown אמיתי (select) ולא כפתורים מוערמים.

## מצב נוכחי
נבנה פרוטוטייפ React מלא (קובץ מצורף `photographer-flow-prototype.jsx`) שממחיש את כל הזרימה, הלוגיקה, והעיצוב הנ"ל עם נתונים מדומים (persist דרך window.storage). הצלם אישר את כל הזרימה בדמו.

**המשימה הבאה:** להקים פרויקט Next.js אמיתי + Supabase (Postgres, Auth) + Vercel hosting, להעביר את הלוגיקה מהפרוטוטייפ (מבני הנתונים, ה-flows, הרכיבים) למערכת production אמיתית עם הרשמה/התחברות אמיתיים ומסד נתונים אמיתי. האינטגרציות החיצוניות (וואטסאפ, גוגל קלנדר, תשלומים) ייבנו בשלבים מאוחרים יותר.
